# Koop Stufe 1, zwei Spieler laufen zusammen: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Spieler hostet, ein zweiter verbindet sich per Direct IP; beide laufen in derselben Zone und sehen sich gegenseitig.

**Architecture:** `bevy_replicon` + `bevy_replicon_renet2` über UDP, der Host ist Server und Spieler. Der Gast spielt seinen eigenen Helden lokal (ohne Gegner) und schickt seine Position; der Host bewegt eine Puppe des Gasts und repliziert alle Helden als schlanke Komponenten (`Look`, `NetPos`, `NetHero`). Die Puppe und fremde Helden tragen **nicht** die Komponente `Hero`: die 26 `With<Hero>`-Stellen mit `single()` bleiben für Stufe 1 unberührt, der Umbau auf mehrere Helden kommt in Stufe 2.

**Tech Stack:** Rust, Bevy 0.18.1, `bevy_replicon = "=0.40.4"`, `bevy_replicon_renet2 = "=0.17.0"` (Features `renet_serde`, `client`, `server`, `native_transport`), serde.

**Spec:** `docs/superpowers/specs/2026-10-31-coop-direct-ip-design.md` (Abschnitte „Architektur-Varianten“, „Entdeckung im LAN und Direct IP“, „Stufenplan / Stufe 1“, „Entscheidungen“).

**Referenz-Code (gleiche Versionen, läuft auf diesem Spiel):** `~/.cache/coop-reference/deanmathieson-progression/` (`coop/net.rs`, `coop/wire.rs`, `coop/host.rs`, `coop/client.rs`, `coop/mod.rs`, `units.rs`; MIT OR Apache-2.0, Quelle in `SOURCE.txt`). Für jede replicon-API (`RepliconPlugins`, `ServerPlugin { tick_schedule: None }`, `ServerTick::increment`, `app.replicate::<T>()`, `add_client_message`, `add_server_message`, `Channel`, `FromClient<T>`, `ToClients { targets: SendTargets::.., message }`, `ClientId::Client`, `ClientState`, `Replicated`) dort nachsehen statt raten.

## Global Constraints

- Ports: Spiel **UDP 37373** (`DEFAULT_PORT`), LAN-Suche 37374 (erst Stufe 4). Nicht 5000.
- `MAX_CLIENTS = 3` (vier Spieler mit dem Host).
- `PROTOCOL_ID = 0x5753_5552_5631_0001` („WSURV1“ + Version 1), eigener Wert, nicht Deans.
- Netcode `ServerAuthentication::Unsecure` / `ClientAuthentication::Unsecure` (nur Freunde).
- Replikations-Takt 20 Hz auf der Wanduhr (`Time<Real>`), nicht im Spieltakt.
- Feature `coop` in `survivors-app`, nur nativ: Module unter `#[cfg(all(feature = "coop", not(target_arch = "wasm32")))]`. `warcraft-survivors` schaltet es in seinem `default` ein, `wenilla` nicht.
- Ohne `coop` verhält sich das Spiel exakt wie heute.
- Kein Gedankenstrich U+2014 in Code, Kommentaren, Texten. Kommentare englisch im Stil der Datei, Herkunft übernommenen Codes im Modulkopf nennen.
- Bauen mit `CC=gcc`: `CC=gcc cargo build --profile play -p warcraft-survivors`, Tests `CC=gcc cargo test --profile play -p survivors-app --lib`.

## Review Focus

1. Gast verbindet sich, während der Host schon im Lauf ist: er muss sofort `StartRun` bekommen und in dieselbe Zone gehen, der Host spawnt seine Puppe. Geprüft in Task 6, Schritt 3.
2. Gast schließt das Fenster: der Host entfernt die Puppe ohne Panic, ein späterer Gast bekommt den Platz wieder. Task 4 Test `freed_slot_is_reused`, Task 6 Schritt 4.
3. Falsche Adresse oder Host nicht erreichbar: der Gast bleibt im Menü, eine lesbare Zeile im Log und im Chat, kein Panic. Task 1 Test `bad_addresses_are_refused`, Task 6 Schritt 5.
4. Port belegt (zweiter Host auf demselben Rechner): Fehlermeldung, das Spiel läuft solo weiter. Task 1 Test `a_taken_port_is_an_error`.
5. Unsinnige Bewegungsdaten vom Gast (NaN, unendlich, weit außerhalb der Arena): werden verworfen. Task 4 Test `bad_moves_are_dropped`.
